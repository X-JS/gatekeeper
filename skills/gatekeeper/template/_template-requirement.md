## 四、非功能需求
1. 编码规范：严格遵循根目录 `AGENTS.md` 全局规范（禁止硬编码、禁止 `SELECT *`、禁止空指针风险、禁止裸 `new` 拼接字段）。
2. 异常处理：统一全局异常捕获，返回统一格式响应体，禁止把堆栈/内部错误直接暴露给前端。
3. 安全性：敏感字段（密码、token、密钥等）响应前必须脱敏；禁止将密钥、口令、连接串硬编码或写入日志；业务上要求唯一的字段（手机号、邮箱、用户名等）入库前做唯一性校验并返回友好提示。
4. 接口规范：请求方式默认 POST；确需其他方式（GET/PUT/DELETE）时须在本文件第五节说明理由并经人工确认；所有入参做非空、长度、格式合法性校验；手机号、邮箱等格式字段加正则校验。
5. 性能：单条查询、更新接口响应耗时默认 < 200ms（大数据量等特殊场景以需求文档为准）。

## 五、接口清单（REST风格，默认 POST）

2. 查询：POST /api/xxx/detail
3. 分页查询：POST /api/xxx/list
4. 修改：POST /api/xxx/update
5. 删除：POST /api/xxx/delete
> 若确需 GET/PUT/DELETE 等其他方式，请在对应项后注明理由，并经人工确认。

## 六、数据库变更说明
1. 主键：雪花算法，非空、唯一。
2. 索引：按业务查询字段建立索引，外键/唯一约束在设计中明确。
3. 变更脚本：数据库变更必须生成正向脚本 `crmeb/sql/<分支目录>/update/` 与回滚脚本 `crmeb/sql/<分支目录>/rollback/`，并配套 `order.md`，按 `AGENTS.md` 第四节执行。
4. 通用字段：`create_time`、`update_time`（格式 `yyyy-MM-dd HH:mm:ss`）；逻辑删除字段按现有表约定。

## 七、验收标准
1. 所有接口可正常调用，功能完全匹配需求。
2. 参数校验生效，重复数据、空参数、非法格式必须可拦截并返回统一规范响应。
3. 无硬编码、无 `SELECT *`、无空指针风险，符合 `AGENTS.md` 全局编码规范。
4. 所有新增代码配套基础单元测试，全量测试通过率 100%。
5. 单条查询、更新接口响应耗时 < 200ms。
6. 相关数据库变更脚本（update / rollback / order.md）已生成并随分支留存。
